# 抓取 Skill 分层基准

目标是验证 Skill 是否提高 Agent 对环境的理解、任务完成能力，或降低时间/token成本。
模型候选、几何合格、完整路径、实际动作、物体跟随和稳定释放分别计分。
沿用既有观测、v5 几何、IK、规划、唯一执行 owner 和 HOLD/close；本基准不增加公开 Skill 或调度器。

## 1. 数据与验证层级

| 数据层 | 首批范围 | 可以评估 | 不据此声称 |
|---|---|---|---|
| 真机保存快照 | 7个完整三视角状态，每视角5帧；主批固定每状态3个相近时刻的视角 | 文字定位、深度有效性、跨视角一致性、v5候选、按原qpos的离线完整路径 | 真机抓取成功、动态跟踪、接触或物体位姿绝对精度 |
| 真机缺视角扩展 | 11状态和5状态，均缺左腕 | 两视角专项、缺视角处理 | 完整三视角通过；不能无声混入主批 |
| MuJoCo输入层 | 6种布局×3个位置变体=18个场景 | 同语义输入下的观测、关系目标和候选能力 | 配置加载通过不等于原生运行或抓取成功 |
| MuJoCo运动层 | 每个场景独立通过原生入口/关闭资格后进入 | 完整路径、接近、闭爪、试抬、搬运、释放、退出 | 工具completed或Agent finish不等于物理任务成功 |

首批真机数据使用原 session-left-first-20261011-201432-7980；源路径放在外部运行manifest，
不写死到代码。105对RGB-D对应7个独立状态和21个状态—视角组合，不能作为105个独立任务。
depth_m已经是米；零深度保留为缺失，不能重复乘设备比例。索引、scene、snapshot、context和
生命周期一起绑定；相机角色、内参和相机/双臂时间关联来自原记录，不能用今日qpos代替。

当前reader的最近邻qpos属于离线重建规则。原105帧中60帧的最近qpos在图像之后才可用，
因此基准同时保存“原离线最近邻”和“此前已可用的最新qpos”索引；在线资格必须另用因果规则，
不能把后者的索引存在当成已经接通实时消费者。这里不改变原reader默认或任何时效门禁。

首批缺少逐像素语义真值、实际物体6D位姿和抓取结果。操作者标签只是待验证的任务声明；
需要把图像复核/标注版本固定后才能计算识别正确率。front标定残差和腕部安装标定来源随样本保留。
URDF、mesh、tool profile、envelope及自体过滤策略还需绑定到具体的离线规划批次。

MuJoCo复用已有SceneSpec/scene_suite数据生成入口。第一批选shape_palette、same_color_shapes、
dense_clutter、partial_occlusion、raised_support、wrist_supports，三个位置变体均保留。
场景布局、任务文字和评分对象必须一致；包含红方块的场景不能误写成蓝方块正例。
public_tasks只含id/phase/instruction，native物体pose、body/geom ID、语义mask和评分器文件保持私有。
NN和Agent接收RGB-D、内参、采集时本体状态及真实可保存观测引用，不读配置中的目标pose。

## 2. 三类对照分别冻结

1. **感知对照：** SAM2/Grounding-DINO与SAM3使用相同RGB、文本任务和对应深度。
   保留正确目标、相似外观、遮挡、缺失目标负例。不能给某条件额外人工像素而称纯文字定位优势。
2. **生成与规划对照：** 当前GraspMoE为主要控制，diffusion、Contact-GraspNet、VGN、GraspNet为候选。
   固定同一测量mask/点云、坐标、v5实体几何、开口、过滤、双臂初态及原规划预算。
   模型原帧到DMTAC的变换及模型输入条件需各自核实；旧相机坐标条件提案不得伪装成当前重力对齐推理。
   先比较相同完整路径wall预算，再另做相同提案/查询预算，两个实验不能混算。
3. **Agent抽象对照：** 相同下层能力与任务，对比原始分步工具和目标引用→关系求解→safe执行封装。
   DeepSeek reasoning:max，固定URL、模型、输出预算和请求节奏。工具描述只含必要接口说明。
   采用率、推理轮次、工具次数、输入/输出token和真实任务结果一起统计。

旧版原始实现保留为历史参考；主要消融使用相同底层和环境，单次改变一个因素。
不能把旧机型/旧碰撞配置/旧模型服务的总耗时与新版直接归因为某个Skill增益。
原始完整失败和启动前失败保留；若输入或评分器错误，新批次另固定，不补跑替换旧槽。

## 3. 固定分母与评分

正式单项对照先按以下规模准备，不把准备好的槽当作已启动：

- 真机离线：7状态×5重复×2条件=70槽。双臂结果分列，同一次共享候选生成不重复记两份模型耗时。
- MuJoCo：18场景实例×5重复×2条件=180槽；若原生资格失败，保留对应未启动Agent分母。
- 额外模型与多视角条件另开固定批次，不在结果出来后删掉困难场景或添加只利于新方案的条件。

每槽保存启动记录、输入/源码/权重/config哈希、机器环境、随机种子（若可控）、冷启动与稳态时间、
原始异常、正常关闭回执。开始后无终结记录记missing_result；未开始记unstarted，不能算为模型拒绝。

| 层 | 必需指标 |
|---|---|
| 感知 | 目标存在/缺失、选择正确实例、有效深度占比、测量来源和像素引用、跨视角/复用有效性 |
| 几何 | 原提案→开口→捕获→目标/背景碰撞→接近过滤；原提案与派生变体分开；有候选的输入覆盖 |
| IK/路径 | 起点资格、各阶段端点拒绝、关节限位/包络/碰撞对、首条完整路径时间、查询数、路径长度/回转/执行时间 |
| 物理 | 双侧接触、物体试抬/跟随、冻结手物关系误差、碰撞/掉落、稳定释放及撤手 |
| Agent | 每层实际结果、正确安全拒绝、错误动作尝试、工具采用率、wall、token和推理轮次 |

成功率分别报告已启动和完整声明分母。时间/token主表保留失败与截断；双方完成的配对子集另列，
不能只删掉失败后宣称加速。按同一场景/变体/重复配对，并以源场景为聚合单位；重复不是独立新场景。
报告每场景结果和分布，后续置信区间按源场景重采样。样本不足时标为探索信号，不预设必须提升两项；
能力提高或总体更快任一成立都值得保留，但要同时展示其他指标的变化。

1mm硬穿透、3mm/2°冻结手物关系、50ms缺口和完整稳定窗口保持。模型置信度、规划成功、
动作completed和Agent finish不替代物理评分；不允许weld、在线重锚定或宽松评分制造成功。

## 4. 已落地的报告入口

`scripts/probes/benchmark_grasp_geometry.py`读取已有模型探针的几何结果，不运行模型、设备或仿真。
外部manifest绑定cases、conditions、repeats、全笛卡尔积slots及每个原始freeze/summary记录。
输入NPZ/相机元数据/mask必须与原freeze逐hash一致，重复record不能充作新的重复实验。
生产结果还需绑定实际执行时的freeze哈希及condition_identity（几何profile、执行参数和固定文件内容哈希）。
旧报告缺少这种关联时只保留描述统计，不进入正式配对子集；不能事后把一份无关联报告绑定到新输入上。
记录去重使用报告内容哈希和原record ID，复制或换路径不会变成新重复。
报告保留未启动、缺结果、失败和缺关闭证明，输出有候选覆盖、几何wall和按输入配对的差值。
该报告始终标记task_success_assessed=false，不能当作模型前向速度、可达性或抓取成功报告。

```bash
python scripts/probes/benchmark_grasp_geometry.py \
  --manifest /absolute/path/to/fixed-matrix.json \
  --output /absolute/path/to/new-report.json
```

第一轮复用已关闭的VGN、Contact-GraspNet和GraspNet两种参考平面实验，各12槽、合计36槽。
它们只有3个图像—目标输入、来自2个MuJoCo布局，属于回顾性几何消融；不是新真机实验或正式主基准。
真机清单、18场景配置、任务标注和后续模型/规划分母独立保存，不把旧几何结果迁入新数据集分母。

后续实际运行继续用原模型服务、replay_bimanual_grasp_snapshot、Gateway和RPent运行/记录入口；
报告层只汇总证据，不另建执行owner。SceneSpec公共套件和实验产物保持在原归属目录，按固定SHA引用，
本增量不重复吸收已集成的场景、坐标、Skill或安全代码。
