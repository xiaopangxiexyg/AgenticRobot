# 抓取 Skill 后续开发：目标、证据与逐项推进

更新：2026-10-25。任务归属仍为 `codex/skill-system-20261019`。
本说明重新核对了用户总建议的全部方向；后端对照是其中一部分，完整抓放能力才是目标。

## 1. 最终要交付什么

Agent 用物体、已保存的真实观测引用和任务约束表达意图。下层分别负责测量、目标关系、
候选生成、运动规划、物理执行和效果验证，以简洁的结果及必要失败原因返回 Agent。
减少 Agent 手工复制坐标、重复识别和逐步编排的负担，同时保留底层分层及唯一执行 owner。

可复用信息包括 RGB-D/SAM 测量、标定、已知尺寸/CAD、此前真实取得的物体状态。
历史测量可以继续用于静态目标；它不是当前跟踪结果。仿真私有 pose、分割真值只用于独立
评估和原物理 guard，不能构造 Agent 或规划器的目标输入。

有效增量至少满足一项：任务能力提高，或相同任务质量下完整时间/token 成本下降。
模型裸速度、接口接通、离线测试通过不单独构成 Skill 收益。

## 4. 下一阶段按四条可交付链推进

### A. 分割与测量 → 可复用目标 → 关系运动

近期先把有效 SAM3 后端与正在整合的 anchor/空间目标组组合验收。复用原选点算法：
同一认证 RGB-D cut、mask 内部有效深度、原光学坐标与工具标定；保留完整 mask 边界给
几何/碰撞消费者，不能把定位核心区当成物体完整占用。

Agent 的常用入口应接收目标引用、关系/偏移和姿态约束，在下层完成解析、求解和 safe
执行，返回完成或有意义的失败。底层仍分别保留观测、关系查询、规划与执行端口。
不增加每种模型一个 Skill，不创建第二套世界状态缓存。

再增加显式物体状态生命周期：保存来源、观测时刻、坐标和不确定度；区分 observed、
predicted、occluded、lost。对象移动、接触、支撑变化、跟踪丢失触发失效/重观测，
不通过刷新时间把历史点装成新测量。原静态 anchor 默认不改。

验证顺序：同帧三维误差/深度有效率→遮挡与移动的身份保持→原 safe 原生资格及清理→
DeepSeek max 多场景重复。连续跟踪实验需要新的连续 RGB-D，不能用静态跨相机快照替代。

### B. 提案覆盖 → 完整可执行抓取链

先用新原生日志定位 16 s 级 arm-selection：是哪一阶段、哪组约束、哪种候选顺序消耗预算。
复用现有计时、实际候选与拒绝码，不再制造一个与主线并行的 planner。

Contact-GraspNet 作为独立模型实际准备；它与 GraspNet baseline 不是同一模型。
官方源已固定，兼容环境/算子与权重资格通过后，再喂相同 RGB-D/目标 mask，进入原 v5
完整工具变换、几何、IK、可见场景及路径链。适配的 gripper 假设必须显式，不能只对齐画图。

候选策略先做影子对照：不同方向/接触区域/宽度的保留与去重、连续 pre/contact/lift 分支，
原有排序对 beam=1/4/8。分别固定候选数和总 wall 预算；关注首次完整链、feasible@N、
路径长度/回转幅度、假阴性和后继可行性，不只比较原始分数或前五个 proposal。

需要加入可行的试抬、搬运、放置、开爪和退出检查，避免当前可接近但无后继的抓姿。
官方多解 IK、VAMP/CAPT、cuRobo 的引入各自是可选候选/影子阶段；必须计入转换、
准备、GPU 排队与原精检成本，不改变唯一 dispatch、C2 轨迹或 HOLD。

### C. 真实接触 → 携物 → 稳定放置

携物缺陷单列，不阻塞 A/B。先冻结两种候选，每种对比等时长静态 HOLD 与固定搬运，
各三重复，共 12 槽；从原生入口到正常清理，记录接触对/力、夹爪开度/饱和、物体相对
TCP 的 SE(3)、支撑接触与时间缺口。先区分闭爪问题、静态滑移和运动引起的滑移。

61 g 实测质量可用，但不能推导已辨识惯量；20×15 mm 感知区不能代替完整接触几何。
在证据指出原因后再做有界局部闭爪/力/滑移修正，而非先增大摩擦或放宽穿透/冻结关系。

放置表示为物体目标区域、支撑与姿态约束，使用已验证的手物关系规划完整实体占用。
释放验收至少包含脱离夹爪、有效支撑、目标误差/速度稳定窗口和退开后的最终状态。
失败恢复根据空手/持物/不确定状态从当前测量重新规划，不能盲目回原起点。

### D. 组合执行与并行降低 Agent 往返

按风险和现有复用程度依次做：

1. 同一观测快照的多目标/多计算；模型特征、几何结构和合法历史测量按原 owner 复用。
2. 候选及 IK 批处理，共享调用预算和可取消边界；不并发使用不支持并发的 SDK 实例。
3. 下层组合正常阶段，复用 RPent `ToolExecution`/后台投递及 Gateway 操作状态。
   普通阶段只记录进度；失败需要策略选择、歧义或任务变化时才唤醒 Agent。
4. 原观察 owner 的只读事件与运动并行：物体跟随、支撑改变、接触异常；不产生第二个
   相机/rig/source，不把预测作为观测，也不将 pending/取消 ACK 当作下层 HOLD。
5. 最后才试“执行已证明可停的前缀，同时求后继”。冻结当前状态、几何、有效区间及
   可停止边界；抓取未验证前不得投机执行搬运，取消时保留 worker 退出和 owner 证明。

比较整个任务的推理轮数、关键路径、p50/p95、token、恢复及取消时延。
哈希与审计由架构保存；模型只见可调用引用、必要测量/坐标/新鲜度、状态及失败原因。
不删除底层身份/权限/TTL/完整审计，不把提示词拟合当成组合 Skill 优化。

## 6. 下一批实验如何保证可信

- 新批先做任务语义资格：声明目标确实存在，正/负例分开；真值只在独立评价端。
  条件共享原图/深度、起始姿态、几何和任务文本，差异只来自待验证功能。
- 按布局族划分开发/验证/未见场景；增加尺寸、高度、纹理、遮挡、同色干扰、近障碍、
  支撑面、目标移动和手物相对姿态。复杂度递增，不只换随机种子。
- 先原生入口/安全拒绝/正常清理，再 Agent。失败保留、未启动另列，固定脚本/输入/源码
  后不热改、不替换失败、不自动重跑。重型 GPU/native 用原资源锁串行。
- API 使用相同精确 URL/model、`reasoning_effort=max`、输出预算；按账户限制统一节流，
  429、记录器错误、输入无目标、错误推理、规划拒绝、执行失败分别计数，不偷偷换 provider。
- 成本同时报告全部尝试和配对均完成子集；按任务/布局和重复报分布，不只报总体平均。
  运动完成、正确拒绝、接触、物体跟随、稳定释放、Agent 理解和物理任务成功分别评分。
